# Открытые вопросы к Paynet

Всё, что в документации помечено как **Draft / Черновик / Ciornă**, и расхождения между источниками. Источники: `paynet.ecom.api.V1.pdf`, `PaynetEcomV0.5.pdf`, OpenAPI, примеры ответов в `api_paths.json`, код портала, инструкция мерчанту от 26.05.23.

| # | Вопрос | Что сейчас в документации | Где |
|---|---|---|---|
| 1 | Значения `status` платежа в API v1 | Значения из спецификации v0.5 (1 Registered, 2 Customer verified, 3 Initialized to be paid, 4 Paid), помечены как черновик. Платёж считается оплаченным при `PAID`-уведомлении или заполненном `paidDate`. | Statuses and errors |
| 2 | Кодировка строки для подписи при кириллице/диакритике | Портал считает по UTF-8; пример C# в v0.5 — Windows-1251. Для латиницы результат одинаковый. | Signatures |
| 3 | Боевой базовый URL API | «Выдаёт Paynet при запуске». В PDF V1 указан `merchant-ecom-api-v2-test.paynet.md/api`, портал использует `ecom-api-test.paynet.md` (подтверждено инструкцией мерчанту). | Getting started, Go-live |
| 4 | Тестовые карты для отказа и 3-D Secure | Опубликована только успешная Visa `4111 1111 1111 1111`, 12/27, CVV 777 (срок карты истекает в 12/2027). | Testing |
| 5 | Два секретных ключа в тесте | Ключ checkout `F90D6485-…` (из кода портала) и ключ уведомлений `D9873689-…` (из инструкции) описаны как разные. | Getting started, Signatures |
| 6 | `EventType` уведомления | Спецификация v0.5 — `PAID` и `Paid`, симулятор портала — `PAID`/`FAIL`. Документация: `PAID`, сравнивать без учёта регистра. Существует ли реальное событие `FAIL`? | Notifications |
| 7 | Заголовок `Authorization` в уведомлении | В v0.5 указан `Header(Authorization) bearer …` для уведомления. В документации не упоминается, проверяется только `Hash`. | Notifications |
| 8 | Формат ошибок | Реальные примеры: `{status, message, code, traceId, details}`; ответы 401 — с заглавными ключами; `/auth` — массив. В PDF V1 описан другой формат `errorInfo{…ppResponseCode…}`. | Statuses and errors |
| 9 | Отображается ли заказ hosted checkout в `GET /api/order/merchant/{id}` | Предполагается «да» (так работает симулятор уведомлений портала). | Integration options |
| 10 | Протокол v0.5 (`/acquiring/SetEcom`) | Описан как устаревший («old» в портале). Поддерживается ли он для новых мерчантов? | Hosted checkout |
| 11 | Повторное использование `Order` | Документация требует уникальный `Order`, но не описывает, какая ошибка возвращается при повторе. | Testing |
| 12 | Часовой пояс `ExpiryDate` | Формат без пояса (`YYYY-MM-DDTHH:mm:ss`); в каком поясе его интерпретирует Paynet — не указано. | Server-to-server |
