# Открытые вопросы к Paynet

Всё, что в документации помечено как **Draft / Черновик / Ciornă**.

| # | Вопрос | Что сейчас в документации | Где |
|---|---|---|---|
| 1 | Значения `status` платежа и их смысл. Гипотеза (из прошлых обсуждений, не подтверждена): 1 Registered, 2 Customer Verified, 3 Initialized to be Paid, 4 Paid, 5 Expired, 41 PartialCancel. Факт с тестового API 09.11: заказ с истёкшим `expiryDate` по-прежнему возвращает `status` = `1` — значит, 5 Expired не выставляется автоматически или означает другое | «Описание значений будет опубликовано позже»; новый заказ — `status` = `1`; оплачен = уведомление `PAID` или заполнен `paidDate` | Errors and statuses |
| 2 | Кодировка `PayerName` / `PayerSurname` в уведомлении: в боевом уведомлении 06.11 имя с диакритикой пришло как `Tom?a`. Это ошибка кодировки на стороне Paynet? Может ли так же испортиться `Customer` (он входит в подпись)? | не описано | Notifications |
| 3 | Формат ошибки `errorInfo` (400 при неверном JSON / нет обязательных полей) — это намеренно? Планируется ли один формат ошибок для всех случаев? | описаны оба формата, как отвечает сервер | Errors and statuses |
| 4 | Подпись MD5: планируется ли новая версия (например, HMAC-SHA256) с периодом совместимости? | описан текущий MD5 | Signatures |

## Закрытые вопросы (ответы Paynet)

| Тема | Ответ |
|---|---|
| Боевой URL API | `https://ecom-api.paynet.md`, пути как в тесте |
| Тестовые карты отказа / 3DS | нет; тестируется только успешный платёж; при неуспехе — редирект на `LinkUrlCancel` |
| Уведомления | только `PAID`; при неуспехе уведомления нет; `FAIL` добавят позже |
| Секретные ключи | два разных: для формы checkout и для уведомлений |
| Заказ hosted checkout в API | виден в `GET /api/order/merchant/{Order}` |
| Протокол v0.5 | убрать из документации |
| Повтор `Order` | те же данные → тот же платёж; другие данные или уже оплачен/в обработке → `500 TECHNICAL_ERROR`; в форме — страница «Plata a fost respinsă» |
| Часовой пояс `ExpiryDate` | время Кишинёва |
| Формат ошибок | `status` / `message` / `code` / `traceId` / `details`; `401` — с большой буквы (`Status`…); неверный JSON — `errorInfo` (проверено на тестовом API 09.11) |
| Регистр полей запроса | не важен: unlink принимает `CardLinkHash` и `cardLinkHash` (проверено 09.11) |
| Ключи уведомления | `Id` / `ExternalId` подтверждены боевым уведомлением 06.11; `ID` / `ExternalID` 06.11 отправлял симулятор портала v2 (ошибка, исправлена в v3) |
| Кодировка подписи | UTF-8 |
| Заголовки уведомления | только `Hash` и `Content-Type`; ключи `Id` / `ExternalId` |
| `MoneyType` в уведомлении | `CARD`, `APPLEPAY`, `GOOGLEPAY`, `MIA_QR`, `PAYNET`, `CASH_INVOICE` |
| Apple Pay / Google Pay в запросе | показываются при `MoneyType` = `Card` и `All` |
| `PaidAmount` | должен равняться `Amount`; отличается только при официально согласованной акции; мерчант получает `PaidAmount` − комиссия |
