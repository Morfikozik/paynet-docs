# E-commerce: варианты интеграции

Paynet e-commerce позволяет интернет-магазину принимать оплату картой (включая Apple Pay и Google Pay), кошельком Paynet, мгновенными платежами MIA и наличными по счёту. Интегрироваться можно тремя способами. Все они заканчиваются на одной и той же платёжной странице Paynet, поэтому вы сами никогда не собираете данные карт.

| | Server-to-server API | Hosted checkout (client-server) | Готовые плагины |
|---|---|---|---|
| Как заказ попадает в Paynet | ваш **бэкенд** вызывает `POST /api/order` с Bearer-токеном | **браузер** покупателя отправляет в Paynet подписанную HTML-форму | плагин делает это сам |
| Чем защищён запрос | токен доступа (`/auth`) | `Signature` = MD5 + Base64 с вашим секретным ключом | настройки плагина |
| Что вы получаете | `paymentId` + `paymentLink` в JSON | покупатель сразу попадает на платёжную страницу | — |
| Статусы, возвраты, выписки | да, тот же API | да, через server-to-server API (заказы ищутся по вашему `Order`) | зависит от плагина |
| Подходит для | собственных магазинов и приложений с бэкендом | простых сайтов, быстрого старта без API-клиента | WordPress/WooCommerce, OpenCart, PrestaShop, Magento, CS-Cart, Shopify |

## Как выбрать

- **У вас есть бэкенд и нужен полный контроль** → [Server-to-server](#/guides/server-to-server). Самый гибкий вариант, `paymentId` вы получаете сразу.
- **Нужна только кнопка «Оплатить» без вызова API для создания заказа** → [Hosted checkout](#/guides/hosted-checkout). Бэкенд всё равно нужен для расчёта подписи: секретный ключ не должен попадать в код браузера.
- **Магазин работает на поддерживаемой CMS** → скачайте плагин в разделе **E-commerce → Плагины**. Shopify подключается через Cybersource.

## Что нужно любой интеграции

1. **Callback URL** для [уведомлений](#/guides/notifications). Paynet вызывает его, когда платёж оплачен (уведомления приходят только об успешных платежах). Сообщите этот URL в Paynet.
2. **Проверка подписи** каждого уведомления, см. [Подписи](#/guides/signatures).
3. **Проверка статуса** перед отгрузкой: `GET /api/order/{paymentId}` или `GET /api/order/merchant/{order}`.
4. **Уникальные номера заказов** (`Order`) на вашей стороне: один заказ магазина = один `Order`.
5. **Два секретных ключа** от Paynet: один для подписи hosted checkout, другой для уведомлений.

## Общая схема

```text
Покупатель      Ваш магазин (бэкенд)                Paynet
   | оформление |                                     |
   |----------->| 1. создать заказ (API или форма)    |
   |            |------------------------------------>|
   | 2. переход на платёжную страницу                  |
   |-------------------------------------------------->|
   |              3. оплата на странице Paynet          |
   |<--------------------------------------------------|
   | 4. возврат на LinkUrlSuccess / LinkUrlCancel       |
   |            | 5. уведомление (POST, заголовок Hash)|
   |            |<------------------------------------|
   |            | 6. проверить Hash и статус, отгрузить |
```

Возврат покупателя на `LinkUrlSuccess` — это только шаг интерфейса. **Не считайте заказ оплаченным только потому, что покупатель вернулся на страницу успеха.** Опирайтесь на уведомление и/или API статуса.

Если оплата не прошла, покупатель перенаправляется на `LinkUrlCancel`. О неуспешных платежах Paynet уведомления не отправляет.
