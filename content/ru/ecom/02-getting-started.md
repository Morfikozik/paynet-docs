# Быстрый старт

Эта страница проведёт вас от нуля до успешного тестового платежа примерно за 10 минут, используя общий тестовый аккаунт и панели «Test API Request» портала. Покупатель платит на платёжной странице Paynet, поэтому вы не работаете с данными карт.

## Окружения

| Что | Тест | Продакшн |
|---|---|---|
| Базовый URL API | `https://ecom-api-test.paynet.md` | `https://ecom-api.paynet.md` |
| URL формы hosted checkout | `https://test.paynet.md/ecom/checkout` | `https://paynet.md/ecom/checkout` |

В обоих окружениях пути одинаковые (`/auth`, `/api/...`).

## Учётные данные

| Что | Тест (общий) | Продакшн |
|---|---|---|
| Пользователь API (`username` / `password`) | `771064` / `sLgMnGWJ` | выдаёт Paynet вашей компании |
| Код мерчанта (`Merchant`) | `265505` | выдаёт Paynet |
| Код торговой зоны (`SaleAreaCode`) | `onlidocumentation_md` | выдаёт Paynet (по одному на сайт/магазин) |
| Секретный ключ для подписи hosted checkout | `F90D6485-9CCC-458B-96A3-8958AF9B4458` | выдаёт Paynet, храните в секрете |
| Секретный ключ для уведомлений | `D9873689-E5F8-4272-A67F-0D8BA3F9BAA7` | выдаёт Paynet, храните в секрете |
| Тестовая карта | Visa `4111 1111 1111 1111`, срок `12/27`, CVV `777` | реальные карты |

Paynet выдаёт **два разных секретных ключа**: один подписывает форму hosted checkout, другой — уведомления. Не путайте их.

> **Примечание:** тестовые данные выше публичны намеренно и общие для всех, кто тестирует на портале. Никогда не используйте их в продакшне и никогда не кладите боевые секреты в код фронтенда.

## Первый тестовый платёж (server-to-server)

### Шаг 1. Получите токен доступа

В боковом меню откройте **E-commerce → Методы API → Аутентификация и авторизация** и нажмите **Test API Request**. Логин и пароль не меняйте.

```http
POST https://ecom-api-test.paynet.md/auth
Content-Type: application/json

{ "grantType": "password", "username": "771064", "password": "sLgMnGWJ" }
```

Ожидаемый результат: HTTP `200` и `access_token` (действует около 4 часов, см. `expires_in`). Портал запоминает токен и сам добавляет его в следующие запросы как `Authorization: Bearer <token>`.

### Шаг 2. Создайте заказ

Откройте **E-commerce → Методы API → Создание операции** и нажмите **Test API Request**.

Портал сам подставляет уникальный номер `Order` и `ExpiryDate` на завтра, поэтому пример работает без правок. Если меняете запрос вручную, помните:

- один заказ = один новый номер `Order`;
- `ExpiryDate` должна быть в будущем, формат `YYYY-MM-DDTHH:mm:ss`, местное время Кишинёва;
- суммы — целые числа в минимальных единицах: `300` = 3,00 MDL.

Ожидаемый результат: HTTP `200`, `paymentId`, `status` `1` и `paymentLink` вида `https://test.paynet.md/ecom/getecom/317184?s=…`.

### Шаг 3. Оплатите на платёжной странице

Откройте `paymentLink` в браузере и оплатите тестовой картой `4111 1111 1111 1111`, `12/27`, CVV `777`. После оплаты вы вернётесь на `LinkUrlSuccess`.

### Шаг 4. Проверьте статус платежа

Откройте **E-commerce → Методы API → Получить операцию по номеру заказа мерчанта**, введите ваш номер `Order` и выполните запрос. Вы увидите данные платежа; у оплаченного платежа заполнен `paidDate`.

### Шаг 5. Проверьте уведомление (webhook)

Откройте **Общее → Уведомления → Симулятор уведомлений**. Введите ваш callback URL, секретный ключ уведомлений и номер `Order`, затем нажмите **Get** и **Send notification**. Портал отправит на ваш URL смоделированное подписанное уведомление `PAID`, чтобы вы проверили свой обработчик. Подробнее: [Уведомления](#/guides/notifications).
