# Пример магазина (Node.js)

Готовая минимальная интеграция server-to-server: один сервер на Node.js 18+ без внешних библиотек. Исходный код: [paynet-example-shop-node.zip](sdk/paynet-example-shop-node.zip).

> **Важно:** этот пример проверяется сквозным тестом на тестовой среде Paynet: робот покупает товар в примере, оплачивает его тестовой картой, отправляет уведомление и делает возврат. Поэтому код примера заведомо рабочий.

## Запуск

Пример — готовый интернет-магазин, подключённый к тестовой среде Paynet. Он запускается на вашем компьютере; кроме Node.js ничего устанавливать и настраивать не нужно.

### Перед началом: Node.js

Нужен **Node.js 18 или новее**. Откройте командную строку:

| Система | Как открыть |
|---|---|
| Windows | **Win+R** → наберите `cmd` → **Enter** |
| macOS | программа **Терминал** (Программы → Утилиты) |
| Linux | **Терминал** (обычно **Ctrl+Alt+T**) |

Введите команду и нажмите **Enter**:

```
node --version
```

Если появился номер версии (например, `v22.11.0`), всё готово. Если появилась ошибка, установите Node.js с https://nodejs.org (кнопка **LTS**), закройте командную строку и откройте её заново.

### Шаг 1. Скачайте архив и запустите магазин

Скачайте [paynet-example-shop-node.zip](sdk/paynet-example-shop-node.zip). В командной строке введите по очереди, нажимая **Enter** после каждой строки:

```
cd Downloads
tar -xf paynet-example-shop-node.zip
cd node-shop
node server.mjs
```

| Команда | Что делает |
|---|---|
| `cd Downloads` | переходит в папку «Загрузки», куда браузер сохранил архив |
| `tar -xf …zip` | распаковывает архив (Windows 10/11, macOS), появляется папка `node-shop` |
| `cd node-shop` | переходит в папку магазина |
| `node server.mjs` | запускает магазин |

**Linux:** вместо `tar -xf paynet-example-shop-node.zip` введите `unzip paynet-example-shop-node.zip` (стандартный `tar` в Linux не открывает `.zip`; если команды `unzip` нет: `sudo apt install unzip`).

Появится строка `Demo shop on http://localhost:3000 …`. **Не закрывайте это окно**: пока оно открыто, магазин работает. Остановить магазин — **Ctrl+C**.

> Архив сохранился не в «Загрузки»? Вместо `cd Downloads` наберите `cd ` с пробелом (в Windows — `cd /d ` с пробелом) и перетащите мышью в окно командной строки **папку, в которой лежит архив**: путь вставится сам. Перетаскивайте папку, а не сам архив `.zip`. В Linux с русским интерфейсом папка может называться `Загрузки`.

### Шаг 2. Оплатите тестовый заказ

Откройте в браузере http://localhost:3000, нажмите **Buy** и оплатите тестовой картой: номер `4111 1111 1111 1111`, срок `12/27`, CVV `777`. После оплаты вас вернёт в магазин.

### Шаг 3. Отправьте уведомление об оплате

Откройте http://localhost:3000/orders. Заказ в состоянии **`pending`**, и это нормально: магазин отмечает заказ оплаченным **только после уведомления от Paynet** — так же должен работать ваш настоящий магазин. Paynet отправляет уведомления на callback URL вашего мерчанта, и до `localhost` они не доходят. Поэтому во время разработки уведомление отправляют сами: скрипт проверит платёж через API, соберёт и подпишет уведомление так же, как Paynet.

Откройте **вторую** командную строку и введите, подставив номер своего заказа из колонки **Order**:

```
cd Downloads/node-shop
node tools/send-test-notification.mjs <Order>
```

Например: `node tools/send-test-notification.mjs 1794411831126`. Готовую команду для каждого заказа в состоянии `pending` магазин показывает на странице заказов.

### Шаг 4. Проверьте результат

Обновите http://localhost:3000/orders: заказ теперь **`paid`**, рядом кнопка возврата — можно попробовать вернуть деньги.

### Если что-то не получилось

| Сообщение | Причина и решение |
|---|---|
| `'node' is not recognized…` / `command not found: node` | Node.js не установлен или командная строка открыта до установки. Установите Node.js и откройте командную строку заново |
| `The system cannot find the path specified` / `No such file or directory` после `cd Downloads` | Архив лежит в другой папке. Воспользуйтесь подсказкой под шагом 1 |
| `The directory name is invalid` | Вы перетащили архив `.zip`, а не папку. Перетащите папку, в которой лежит архив |
| `tar: This does not look like a tar archive` | У вас Linux: вместо `tar -xf` используйте `unzip paynet-example-shop-node.zip` |
| `Cannot find module …server.mjs` | Командная строка открыта не в папке `node-shop`. Повторите шаг 1 |
| `EADDRINUSE … 3000` | Магазин уже запущен в другом окне. Закройте это окно (или нажмите в нём **Ctrl+C**) и запустите снова |
| `Payment is not paid (status 1)` | Оплата заказа не завершена. Оформите новый заказ и оплатите его до конца |
| Заказ остаётся `pending` | Уведомление не отправлено. Выполните шаг 3 |

## Что внутри

| Файл | Что делает |
|---|---|
| `server.mjs` | Магазин: товар, создание заказа, переход на оплату, страницы возврата, приём уведомлений, возвраты |
| `paynet-client.mjs` | Клиент API: кэш токена, создание заказа с безопасным повтором, поиск платежа, возврат |
| `paynet-notifications.mjs` | Обработчик уведомлений — тот же код, что в разделе [Уведомления](#/guides/notifications) |
| `store.mjs` | Хранение в JSON-файле — замените своей базой данных |
| `tools/send-test-notification.mjs` | Отправка подписанного уведомления `PAID` на ваш адрес |

## Какие правила показывает пример

| Шаг | Как сделано в примере | Правило |
|---|---|---|
| Создание заказа | Уникальный `Order`; тело запроса сохраняется до вызова Paynet | Повтор — только с тем же телом ([Повтор номера заказа](#/guides/errors-and-statuses)) |
| Срок оплаты | `ExpiryDate` = сейчас + 1 день по времени Кишинёва | `Europe/Chisinau` |
| Возврат покупателя | Страница проверяет `status` через API, а не верит переходу | Переход на `LinkUrlSuccess` — не доказательство оплаты |
| `status` = `1` | Кнопка «продолжить оплату» по той же ссылке | Покупатель не оплачивал |
| `status` = `3` | Страница ждёт и обновляется | Банк ещё отвечает, новый заказ не создавать |
| `status` = `5` | Кнопка «попробовать снова» создаёт новый заказ с новым `Order` | Заказ после отказа закрыт |
| Уведомление | Подпись, один раз на `Payment.Id`, сразу `200`, затем сверка через API | [Что защищает подпись](#/guides/notifications) |
| Возврат | Только при `status` = `4`, не больше `PaidAmount`, один раз | [Возвраты](#/guides/errors-and-statuses) |
| Сохранённая карта | `CardLinkHash` из подтверждённого уведомления сохраняется для покупателя | [Сохранение карт](#/guides/saved-cards) |

## Переход в бой

Задайте переменные окружения боевыми значениями — они отличаются от тестовых — и не храните их в коде:

| Переменная | Значение |
|---|---|
| `PAYNET_API_URL` | `https://ecom-api.paynet.md` |
| `PAYNET_USERNAME`, `PAYNET_PASSWORD` | боевые доступы API |
| `PAYNET_SALE_AREA` | ваш код торговой зоны |
| `PAYNET_NOTIFICATION_SECRET` | боевой ключ уведомлений |
| `PUBLIC_URL` | адрес вашего магазина (для `LinkUrlSuccess` / `LinkUrlCancel`) |

Замените `store.mjs` своей базой данных и пройдите [чек-лист запуска](#/guides/go-live).
